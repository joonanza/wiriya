# เชื่อมต่อฐานข้อมูล (Supabase)

ถ้ายังไม่ได้เชื่อม แอปจะทำงานใน **โหมดเก็บข้อมูลในเครื่อง** คือข้อมูลลูกค้าและประวัติอยู่ในเบราว์เซอร์ของมือถือเครื่องนั้นเท่านั้น
เมื่อเชื่อม Supabase แล้วจะได้:

- ข้อมูลลูกค้าและประวัติงานเก็บบนคลาวด์ เปิดจากมือถือ/คอมเครื่องไหนก็เห็นข้อมูลเดียวกัน
- เรทราคาที่ตั้งในหน้า "ตั้งค่า" ใช้กับลูกค้าทุกเครื่องทันที
- ลูกค้ากด "ส่งคำขอจอง" จากหน้า `customer.html` แล้ว**เด้งแจ้งเตือนในแอปคนขับทันที** (มีเสียง + สั่น + การแจ้งเตือนของเบราว์เซอร์) และบันทึกไว้ในหน้า "ประวัติ"
- ค่าใช้จ่ายที่บันทึกในแดชบอร์ดเก็บบนคลาวด์

> การแจ้งเตือนทำงานเมื่อเปิดแอปค้างไว้ในเบราว์เซอร์ (แท็บเบื้องหลังได้) ถ้าปิดเบราว์เซอร์ไปแล้ว จะเห็นคำขอเมื่อเปิดแอปครั้งถัดไป
- หน้าของคนขับต้องล็อกอินก่อนใช้

## แจ้งเตือนผ่าน LINE OA
หลังตั้งค่า Supabase เสร็จแล้ว ทำต่อตาม [line-oa-setup.md](line-oa-setup.md) เพื่อให้คำขอจองเด้งเข้า LINE ของคุณ

## ค่าใช้จ่าย
แพ็กเกจ Free ของ Supabase เพียงพอสำหรับคนขับรายเดียว (ฐานข้อมูล 500 MB ≈ หลายแสนรายการ)
⚠️ โปรเจกต์ฟรีจะ**หยุดชั่วคราวถ้าไม่มีการใช้งาน 7 วัน** (กดเปิดใหม่ได้ใน Dashboard ข้อมูลไม่หาย)

## ขั้นตอน (ประมาณ 10 นาที)

1. **สร้างโปรเจกต์**
   - สมัครที่ https://supabase.com → New project
   - Region: **Southeast Asia (Singapore)** (ใกล้ไทยที่สุด)
   - ตั้ง Database password แล้วเก็บไว้

2. **สร้างตาราง**
   - เมนู **SQL Editor** → New query → วางเนื้อหาไฟล์ `supabase/schema.sql` ทั้งหมด → **Run**
   - ควรเห็นตาราง `customers`, `quotes`, `settings`, `expenses` ในเมนู Table Editor

3. **สร้างบัญชีคนขับ + ปิดการสมัครเอง** (สำคัญมาก)
   - **Authentication → Users → Add user → Create new user** ใส่อีเมลและรหัสผ่านของคุณ (ติ๊ก Auto Confirm)
   - **Authentication → Sign In / Providers** → หัวข้อ **User Signups** → ปิด **"Allow new users to sign up"** → Save
     (ลิงก์ตรง: `https://supabase.com/dashboard/project/<project-ref>/auth/providers`)
   - **ชั้นป้องกันที่ 2:** `schema.sql` ล็อกสิทธิ์ไว้ที่อีเมลในตาราง `public.drivers` (ตั้งไว้เป็น wiriya.ii1998@gmail.com)
     ต่อให้มีคนสมัครบัญชีได้ ก็จะไม่เห็นข้อมูลลูกค้าเลย
     - เพิ่มคนขับ: SQL Editor → `insert into public.drivers (email) values ('อีเมล');`

4. **เอา key มาใส่ในแอป**
   - **Project Settings → API**
   - คัดลอก **Project URL** และ **anon public** key (ในหน้าใหม่อาจชื่อ **Publishable key** ขึ้นต้น `sb_publishable_`) ส่งให้ผู้พัฒนา หรือใส่เองในไฟล์ `js/backend-config.js`
   - ❌ ห้ามใช้ **service_role** / **Secret key** ในแอป (key นี้ข้ามระบบความปลอดภัยทั้งหมด)

5. **ย้ายข้อมูลเดิม (ถ้ามี)**
   ข้อมูลที่เคยบันทึกในโหมดเครื่องจะไม่ถูกย้ายอัตโนมัติ เปิดหน้า "ตั้งค่า" แล้วกด "บันทึก" อีกครั้งเพื่อเอาเรทราคาขึ้นฐานข้อมูล

## กันสแปม และ PDPA
- `submit_booking_request` ตรวจข้อมูลก่อนบันทึก:
  - ต้องติ๊กยินยอม (เก็บเวลาที่ยินยอมไว้ใน `consent_at`)
  - เบอร์โทรต้องถูกรูปแบบ และพิกัดต้องอยู่ในประเทศไทย
  - เบอร์/LINE เดียวกันส่งได้ไม่เกิน 3 ครั้ง / 30 นาที และทั้งระบบไม่เกิน 30 ครั้ง / 10 นาที
- หน้าลูกค้ามีช่องกับดักบอต ต้องอยู่ในหน้าอย่างน้อย 3 วินาทีก่อนกดส่ง และเครื่องเดียวกันส่งได้ 1 ครั้ง/นาที
- ลบข้อมูลเก่า: หน้าตั้งค่า → "ลบข้อมูลที่เก่ากว่า 1 ปี" (ฟังก์ชัน `purge_old_data`)
- นโยบายความเป็นส่วนตัว: `privacy.html`
- ทดสอบ schema บน Postgres จริง: `npm run test:sql` (CI รันให้ทุกครั้งที่ push)

## ลิงก์ยืนยันการจอง
- ส่งใบเสนอราคาเมื่อไร ระบบแนบลิงก์ `confirm.html?t=<token>` ให้อัตโนมัติ (token สุ่ม 32 ตัว ≈ 190 บิต เดาไม่ได้)
- ลูกค้ากด **ยืนยัน** → สถานะเปลี่ยนเป็น "ยืนยันแล้ว" และแจ้ง LINE · กด **ขอเปลี่ยนแปลง** → คนขับเห็นข้อความในหน้าประวัติ/หน้าแก้ไข
- หน้ายืนยันเห็นเฉพาะข้อมูลของใบนั้น (เบอร์โทรถูกปิดบางส่วน) ผ่านฟังก์ชัน `get_quote_by_token` / `respond_to_quote`
- ลิงก์หมดอายุเมื่อเลยเวลารับ หรือไม่มีความเคลื่อนไหวเกิน 30 วัน · คนขับแก้ราคาแล้วส่งใหม่ ลิงก์เดิมจะแสดงข้อมูลล่าสุด

## ความปลอดภัย (Row Level Security)

| ใคร | customers | quotes | settings |
|---|---|---|---|
| คนขับ (ล็อกอินแล้ว + อีเมลอยู่ใน `drivers`) | อ่าน/เขียนทั้งหมด | อ่าน/เขียนทั้งหมด | อ่าน/เขียนทั้งหมด |
| ลูกค้า / คนทั่วไป | ❌ | ส่งคำขอได้ผ่าน `submit_booking_request()` เท่านั้น อ่านไม่ได้ | อ่านได้แค่ `fare_config` |

- `anon key` อยู่ในหน้าเว็บได้ เพราะสิทธิ์ถูกจำกัดด้วย RLS ด้านบน
- ฟังก์ชันส่งคำขอจำกัด 30 คำขอ / 10 นาที กันสแปมเบื้องต้น และไม่แก้ข้อมูลลูกค้าเดิม

## ข้อมูลลูกค้าและ PDPA
แอปเก็บชื่อ เบอร์โทร LINE ID และตำแหน่งรับ-ส่งของลูกค้า ซึ่งเป็นข้อมูลส่วนบุคคลตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
- ใช้เพื่อการจองและติดต่อกลับเท่านั้น ไม่ส่งต่อให้คนอื่น
- ลูกค้าขอให้ลบข้อมูลได้ → หน้า "ลูกค้า" → ลบ
- ควรมีข้อความแจ้งการเก็บข้อมูลในหน้าลูกค้า (ทำเพิ่มได้)
